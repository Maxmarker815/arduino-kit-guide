# Правка текста уроков

`course.html` — **источник текста уроков**. Это обычный файл, никакой
сборки из книги больше нет: печатную книгу заморозили, продукт — сайт.
Старый сборщик `сборка/собрать-курс.py` оставлен заглушкой и ничего не
делает; запускать его не надо и не получится.

Файл большой — около 690 КБ. Отсюда все правила ниже.

## Как править

**Только точечно, по якорной строке. Никогда не переписывать файл целиком.**

Вывод любого инструмента может быть обрезан, поэтому содержимое файла
нельзя вставлять обратно из того, что ты прочитал — потеряются куски.

Порядок:

1. `grep -n` — найти якорь: кусок существующего текста, уникальный.
2. `grep -c` — убедиться, что совпадение **ровно одно**.
3. Заменить через `Edit` по точному совпадению или коротким скриптом на
   питоне, который **сам читает файл** и делает `str.replace(a, b, 1)`.
4. Проверить чтением: размер изменился ожидаемо, соседний текст цел.

## Что нельзя ломать

- **Структура урока.** Каждый урок — это
  `<article class="lesson" id="L-proj-6" hidden>`. Идентификаторы
  `L-part-1…L-part-5` и `L-proj-1…L-proj-17` — по ним работает левый
  список и переходы по адресу. Пропадёт — урок исчезнет с сайта.
- **Оглавление урока** — `<nav class="l-toc">` сразу под шапкой проекта.
  Пункты ссылаются на id заголовков вида `s-proj-6-3`. Добавляешь новый
  раздел `<h3 class="h-sub" id="…">` — **добавь и пункт в оглавление**,
  иначе раздел будет, а попасть в него нельзя. Убираешь раздел — убери
  пункт, иначе ссылка будет вести в пустоту.
- **Разметка как у соседей.** `<h3 class="h-sub">`, `<p>`,
  `<ul class="parts-list">`, `<div class="callout">`, `<div class="code">`.
  Свою не изобретать: стили берутся из `styles.css`, который общий на все
  уроки.
- **Ничего в `архив/`.** Там замороженная книга и старый сборщик. Правки
  туда не переносить: книга больше не источник и сознательно устаревает.

## После правки

1. `node --check` по инлайновым `<script>` в `course.html` — правка текста
   не должна была их задеть, но проверить дёшево.
2. Если трогал `site.css` или `kit.js` —
   `python сборка/обновить-версию.py`, иначе у покупателей останется старый
   файл из памяти браузера.
3. Передай работу `kit-check`.
4. Скажи прямо, **какой файл куда лёг и какого он размера**: Максат
   проверяет папки руками.
5. **Не коммить и не пушь.** Это он делает сам.

## Если правку не удаётся записать

Бывало: запись отвечает «готово», а на диске остаётся старая версия.
Проверка одна — **прочитать файл обратно** и сравнить. Не докладывать
«сделано», пока чтение не подтвердило.
